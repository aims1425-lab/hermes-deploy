# Hermes Deploy

Hermes Deploy is an open deployment template for running Hermes Agent in production-like environments using
`hermes` CLI and Docker-friendly configuration.

```bash
curl -fsSL https://raw.githubusercontent.com/aims1425-lab/hermes-deploy/main/install.sh | bash
```

## Features

- One-command install flow that installs Hermes and applies a production template
- Security-oriented defaults such as rate limiting and prompt/tool output controls
- Docker Compose workflow for isolated execution and service health checks
- Telegram and Discord token-based platform configuration
- Systemd user service helper generated by installer on Linux
- Multi-provider defaults via Hermes configuration
- Local validation with a lightweight `make validate` task

## Quick Start

```bash
# 1. One command install
curl -fsSL https://raw.githubusercontent.com/aims1425-lab/hermes-deploy/main/install.sh | bash

# 2. Configure your provider
hermes model

# 3. Start chatting
hermes chat
```

### Docker (recommended for production)

```bash
git clone https://github.com/aims1425-lab/hermes-deploy.git
cd hermes-deploy
cp .env.example .env
# Edit .env with your tokens
docker compose up -d
```

## Configuration

```yaml
# config.yaml (production template)
model:
  default: gpt-4o
  provider: openai

gateway:
  port: 8644
  host: 127.0.0.1
  allowed_user_ids: ["your_telegram_id"]

security:
  rate_limit: 30/minute
  max_turns: 50
  sanitize_tool_output: true

platforms:
  telegram:
    enabled: true
    bot_token: "${TELEGRAM_BOT_TOKEN}"
```

## Deployment Options

| Option | Use Case |
|--------|----------|
| **Docker** (recommended) | Production, isolation, easy updates |
| **Direct install** | Development, single-user |
| **Systemd service** | 24/7 always-on server |
| **Docker + reverse proxy** | Multi-agent, SSL, webhooks |
